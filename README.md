## Featured Project

### OSI Explorer

An interactive networking education application that presents the OSI model as a connected system of layers, protocols, devices, addressing methods, commands, and troubleshooting concepts.

Rather than presenting the OSI model as seven isolated boxes, OSI Explorer shows how technologies such as HTTP, DNS, TCP, UDP, IPv4, ARP, Ethernet, MAC addresses, routing, VLANs, Wi-Fi, copper, and fiber work together.

**Project highlights:**

- Seven-layer interactive OSI overview
- Searchable networking topic encyclopedia
- Complete lessons covering core protocols, addressing, media, and routing concepts
- Connected knowledge map with persistent relationship lines
- Guided 12-step packet journey showing what happens when a user visits a website
- Responsive desktop and mobile layouts
- Keyboard-accessible navigation and reduced-motion support
- Automated GitHub Pages deployment through GitHub Actions

**Skills demonstrated:**

- React application structure and reusable components
- JavaScript data modeling and stable topic IDs
- React Router navigation
- Responsive CSS and accessibility
- Networking concepts and technical explanation
- Git, GitHub Actions, and automated deployment

**Technology:** React, Vite, JavaScript, CSS, React Router, GitHub Actions, GitHub Pages

## Additional Projects

### A-Lab: IT Support Learning Tools

A browser-based portfolio and study environment containing two interactive tools developed with vanilla JavaScript.

The CompTIA A+ Lab Terminal accepts typed commands, returns structured technical content, runs quizzes, and tracks progress across hardware, networking, operating system, and security topics.

The Network Troubleshooter presents scenario-based help desk problems involving APIPA addressing, DHCP failure, WAN connectivity, broadcast storms, and switch-level MAC filtering. Correct and incorrect choices both provide explanatory feedback.

**Skills demonstrated:**

### Neptune 4 Plus MCU Recovery

A documented real-world troubleshooting case involving a failed firmware update on a Klipper-based 3D printer.

I isolated the failure between the Linux host and printer MCU, identified the correct CH340 serial interface and COM port, tested recovery methods, and restored the printer without replacing hardware or reinstalling the host system.

**Skills demonstrated:**

- Hardware and firmware troubleshooting
- Serial communication using UART and COM ports
- Windows Device Manager diagnostics
- Host, firmware, and MCU fault isolation
- Root-cause analysis and technical documentation

[View the recovery case study](https://github.com/Steve-G-Git/neptune-4-mcu-recovery)
